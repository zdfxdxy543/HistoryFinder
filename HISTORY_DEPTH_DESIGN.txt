HistoryFinder 历史深度改造完整设计方案
=======================================

文档状态：建议稿
适用版本：当前 CLI 原型之后的下一阶段
核心目标：把“随机历史事件列表”升级为“可追溯、可推理、有长期后果的历史模拟”


一、现状判断
============

1. 当前项目已经具备的基础
-------------------------

当前实现已经形成了一条完整但较浅的链路：

地理生成 -> 聚落创建 -> 逐年模拟 -> 历史事件 -> 物证生成 -> 物证衰变 -> 玩家调查 -> 叙事输出

值得保留的部分包括：

- 固定 seed 带来的可复现世界。
- 高度、温度、降雨、河流、生物群系和聚落适宜度等地理图层。
- 聚落人口增长、毁灭和废墟状态。
- 已有的战争、灾害、贸易、建设、发现、叛乱等事件类型。
- 石材、金属、羊皮纸、木材、织物和口述传统的差异化衰变。
- 官方、民间和中立叙事声音。
- 本地 LLM 可选、模板模式兜底的叙事架构。

2. 当前历史深度不足的根本原因
-----------------------------

问题不在事件数量，而在事件缺少持续状态、明确动机和后续影响：

- 多数事件由每年独立概率产生，与过去的关系较弱。
- 聚落状态维度少，事件没有足够多的状态可以读取或修改。
- 人物只作为名字出现，没有出生、成长、关系、职位和死亡等生命周期。
- 外交关系没有长期记忆，战争和条约不构成稳定的国际关系史。
- 经济、资源、制度、文化和技术没有形成相互制约的系统。
- 大部分事件发生后立即结束，没有形成跨年延续的历史线程。
- 证据与事件是一对多的直接映射，证据几乎自动给出历史真相。
- 玩家可以直接查看完整年表，调查与推理不是获取历史的必要途径。

因此，当前系统更接近“带物证描述的随机编年史生成器”，还不是“历史因果模拟与考古推理游戏”。


二、产品目标与边界
==================

1. 核心体验目标
---------------

玩家进入一个已经运行数十年至数百年的虚构世界。这个世界中的城市、人物、家族、战争、制度和文化都由可追溯的原因演化而来。玩家不能直接读取完整真相，只能通过遗址、物品、档案、口述传统和不同势力的记录逐步建立自己的历史解释。

一次成功的调查应让玩家经历以下过程：

发现线索 -> 提取事实片段 -> 发现矛盾 -> 建立假说 -> 寻找旁证 -> 修正时间线 -> 得出带置信度的结论

2. 设计目标
-----------

- 事件必须尽量由世界状态和参与者动机触发，而不是纯随机生成。
- 重要事件必须产生跨年的政治、人口、经济或文化后果。
- 人物、家族、势力和聚落必须具有历史连续性。
- 同一个事件应产生立场不同、完整度不同、保存状态不同的记录。
- 玩家看到的是证据所支持的解释，不是数据库中的真实事件对象。
- LLM 只负责表达，不负责决定模拟事实。
- 同一 seed 和同一配置必须生成相同的模拟结果。
- 系统应允许逐步扩展，而不要求一次完成所有文明模拟细节。

3. 非目标
---------

- 不追求现实世界级别的经济学、人口学或军事学精度。
- 不模拟每一个普通居民。
- 不让 LLM 自由修改世界状态或创造未被模拟器确认的事实。
- 第一阶段不要求实时图形地图、战术战斗或复杂资源生产界面。
- 不以事件数量作为历史深度的主要指标。


三、核心设计原则
================

1. 状态先于事件
---------------

事件不再是模拟的起点，而是状态变化的可读记录。例如，“矿工叛乱”不应由 2% 概率直接生成，而应由高矿业人口、低粮食供应、高税率、低统治合法性和活跃反对派共同推动。

2. 所有重要事件都要回答五个问题
---------------------------------

- 为什么现在发生？
- 谁推动了它？
- 谁反对它？
- 它改变了什么？
- 它给后世留下了什么？

不能回答这些问题的事件只能作为低重要度“时代纹理”，不能占据主要历史叙事。

3. 区分四种历史
---------------

- 真实历史 Truth：模拟器内部实际发生的状态变化。
- 当时记录 Record：某个主体对事件的记载，可能有偏见或错误。
- 留存证据 Evidence：经过复制、迁移、灾害和衰变后保存到现在的载体。
- 玩家认知 Knowledge：玩家根据证据建立的事实、关联和假说。

四层之间不得直接等同。

4. 深度来自持续性，而不是事件种类
---------------------------------

优先让已有事件彼此连接，再增加新事件类型。建设、贸易、婚姻、灾害、战争和叛乱已经足以形成复杂历史，关键是让它们产生持续影响。

5. 允许不确定性，但必须可解释
-------------------------------

随机性用于打破僵局、表达人的不确定行为和自然波动，但每次随机选择都必须基于权重和上下文。调试模式应能说明某事件的主要触发因素。


四、目标系统架构
================

建议将系统拆成六层：

1. World State 世界状态层
   保存地理、聚落、人口群体、人物、家族、派系、资源、制度、技术和外交关系。

2. Pressure 压力计算层
   从状态中计算饥荒风险、社会不满、扩张压力、继承危机、贸易需求、宗教冲突等连续指标。

3. Intent and Resolution 意图与结算层
   人物、派系和聚落根据目标提出行动；系统解决冲突，得到成功、失败或妥协结果。

4. Historical Event 真实事件层
   把结算结果写成结构化事实，记录原因、参与者、影响和前置事件。

5. Record and Evidence 记录与证据层
   不同主体针对事件制作记录或物证，并在时间中传播、复制、篡改、损坏、埋藏和失传。

6. Discovery and Narrative 发现与叙事层
   根据玩家实际掌握的证据更新知识图谱，再由模板或 LLM 将允许公开的内容转成文字。


五、时间推进模型
================

1. 年度模拟顺序
---------------

每年按固定阶段运行，避免更新顺序导致隐蔽偏差：

阶段 A：自然环境
- 气候波动、旱涝、资源恢复或衰减。

阶段 B：人口与生产
- 出生、死亡、迁移、粮食生产、资源开采、消费和库存。

阶段 C：社会与政治压力
- 计算民怨、合法性、派系力量、继承稳定度和治安。

阶段 D：行动提案
- 聚落、人物和派系根据目标提出贸易、建设、改革、结盟、征税、袭击等意图。

阶段 E：冲突结算
- 处理争夺同一资源、外交对抗、叛乱、战争和政治竞争。

阶段 F：应用影响
- 修改人口、财富、关系、控制权、职位、技术、制度等状态。

阶段 G：形成历史事件
- 只将达到记录阈值或具有后续意义的变化写入事件库。

阶段 H：形成当时记录和证据
- 由参与方、见证者和机构分别生成不同版本。

阶段 I：证据衰变与传播
- 处理复制、转移、毁坏、埋藏和口述失真。

2. 时间粒度
-----------

- 宏观模拟继续使用“年”作为基本单位。
- 战争、继承危机和叛乱可以作为持续多年的 HistoricalProcess。
- 过程内部可记录开始、转折和结束三个关键节点，无需模拟每一天。
- 低重要度日常事件可按五年汇总，避免事件噪声淹没关键历史。


六、核心数据模型
================

以下字段表示概念设计，实际实现建议使用 dataclass，并为序列化保留 schema_version。

1. Settlement 聚落
-----------------

保留现有字段，并增加：

- controller_faction_id：当前控制势力。
- population_groups：人口群体构成，而不只是总人口。
- food_stock：粮食库存。
- treasury：公共财政。
- production：各类资源年产量。
- demand：各类资源需求量。
- infrastructure：道路、城墙、市场、灌溉、档案馆等等级。
- institutions：税制、继承制、宗教政策、兵役制等制度引用。
- stability：综合稳定度，范围 0 到 1。
- legitimacy：统治合法性，范围 0 到 1。
- security：治安与防御能力。
- cultural_traits：语言、宗教和习俗标签及强度。
- strategic_value：交通、矿产、防御和农业价值的组合。
- active_process_ids：正在经历的危机、战争或建设。

2. PopulationGroup 人口群体
--------------------------

不模拟每个居民，而按具有政治意义的群体聚合：

- id
- settlement_id
- culture_id
- religion_id
- social_class：农民、工匠、商人、贵族、祭司等。
- size
- wealth_share
- political_power
- satisfaction
- grievances：税负、饥饿、宗教压迫、土地、治安等不满值。

人口群体用于解释为什么同一政策会得到不同反应。

3. Person 人物
-------------

只创建对历史可能产生影响的重要人物：

- id、name、birth_year、death_year、alive
- home_settlement_id、current_location_id
- family_id、parent_ids、spouse_ids、child_ids
- faction_id
- roles：统治者、继承人、将军、祭司、商人、学者、叛军领袖等。
- traits：野心、虔诚、残酷、谨慎、魅力、能力等有限数值。
- goals：夺权、致富、复仇、改革、传教、扩张等。
- loyalties：对人物、家族、势力和聚落的关系值。
- reputation：按不同群体分别保存，不设置唯一客观声望。
- known_secret_ids
- memory_event_ids

人物出生事件只有在该人物之后真正进入历史活动时才升级为重要事件；否则只作为普通人口记录。

4. Faction 势力
---------------

- id、name、faction_type
- leader_id
- member_person_ids
- controlled_settlement_ids
- ideology_traits
- resources
- military_strength
- influence_by_settlement
- goals
- legitimacy_claims
- active、founded_year、dissolved_year

势力包括王朝、城市政权、贵族家族、商人联盟、宗教组织和叛军。

5. Relationship 外交与社会关系
--------------------------------

关系必须是长期状态，而不是事件文本：

- subject_a_id、subject_b_id
- trust：信任。
- hostility：敌意。
- dependency：经济依赖。
- fear：威胁感。
- obligation：条约、婚姻或债务义务。
- claims：领土、继承或宗教主张。
- treaty_ids
- last_interaction_year

关系值由具体事件增减，并随时间缓慢回归，而不是每年完全重置。

6. ResourceNode 与 TradeRoute
-----------------------------

ResourceNode：

- 位置、资源类型、储量、开采难度、控制者、发现状态。

TradeRoute：

- 两端聚落、路径成本、通行能力、安全度、主要货物、控制者、活跃状态。

地理通过资源和交通进入历史因果链，而不只影响人口上限。

7. Institution 制度
-------------------

- succession_rule：世袭、选举、强者继承等。
- tax_policy：税率和主要征税对象。
- land_policy
- religious_policy
- military_policy
- archive_policy：记录保存和复制能力。

制度变化应缓慢，但一旦改变会持续影响许多年。

8. HistoricalProcess 历史过程
------------------------------

用于表示跨年过程：

- id、process_type
- start_year、end_year、status
- participant_ids
- origin_event_ids
- pressure_snapshot
- progress
- possible_outcomes
- event_ids

典型过程包括战争、瘟疫、继承危机、迁徙、宗教传播、长期建设和王朝衰落。

9. HistoricalEvent 真实事件
---------------------------

扩展现有事件结构：

- id、year、event_type、title
- actor_ids：主动行动者。
- target_ids：行动对象。
- participant_ids：所有参与者。
- location_ids：允许多地点事件。
- cause_event_ids：直接前置事件。
- process_id：所属历史过程。
- trigger_factors：触发时的关键压力及数值。
- precondition_snapshot：发生前相关状态摘要。
- effects：机器可执行的状态变化列表。
- factual_payload：模拟器确认的客观事实。
- importance：历史重要度。
- visibility：当时有多少人可能知道。
- tags
- narrative_bias 不再属于真实事件本身。

所有 effects 必须先由结算器产生，再应用到世界状态。事件文本不能成为状态变化的唯一来源。

10. HistoricalRecord 当时记录
-----------------------------

- id、source_event_ids
- author_person_id 或 author_faction_id
- created_year、created_location_id
- record_type：法令、账簿、书信、碑铭、歌谣、审判记录等。
- claimed_facts：该记录声称为真的事实。
- omitted_facts：有意或无意省略的事实。
- distortions：夸大、淡化、归因错误、日期误差等。
- perspective：官方、反对派、目击者、后世编纂者。
- intended_audience
- secrecy
- copy_parent_id

11. Evidence 留存证据
---------------------

保留材质、耐久和状态模型，并调整为：

- source_record_id 可选。
- source_event_ids 仅供模拟器内部使用，不直接暴露给玩家。
- physical_features：铭文片段、烧灼、修补、地层、制造方式等。
- retained_claims：当前仍可读取的记录片段。
- provenance_clues：年代、来源地、作者身份等线索。
- contamination：后世混入、错误归档、重刻、伪造等。
- authenticity：真实、复制、伪造、误认，玩家初始不可见。
- accessibility：公开、私藏、埋藏、封禁。
- discoverability：发现难度。

12. PlayerKnowledge 玩家知识
-----------------------------

- discovered_evidence_ids
- known_claims
- inferred_facts
- hypotheses
- entity_links
- confidence_by_fact
- contradictions
- unresolved_questions

玩家知识必须单独保存，不能直接把 known_events 当作唯一进度。


七、压力驱动的事件系统
======================

1. 压力指标
-----------

每年从状态计算一组 0 到 1 或可正可负的指标：

- famine_pressure：需求、产量、库存和贸易输入共同决定。
- unrest_pressure：饥饿、税负、不平等、宗教压迫和近期暴力共同决定。
- succession_pressure：统治者年龄、继承人合法性和派系竞争决定。
- expansion_pressure：人口、资源需求、军事优势和统治者野心决定。
- invasion_risk：邻国敌意、军力差距、边境价值和联盟支持决定。
- trade_pressure：资源互补性、路线成本和市场规模决定。
- reform_pressure：技术、阶层力量和制度不匹配决定。
- migration_pressure：生存条件、战争、安全和邻近吸引力决定。
- cultural_tension：群体差异、政策和历史仇恨决定。

2. 候选事件生成
---------------

每条事件规则声明：

- 必需条件 hard_conditions。
- 倾向条件 score_factors。
- 可参与的主体选择器。
- 互斥规则。
- 冷却时间。
- 可能结果及权重。
- 状态影响。
- 后续过程。
- 记录与证据策略。

示例：叛乱候选规则

必需条件：
- 聚落存活。
- 存在政治力量大于阈值的不满群体或派系。
- unrest_pressure 大于 0.65。

倾向得分：
- 饥荒 +0.20。
- 税率过高 +0.20。
- 统治合法性过低 +0.25。
- 邻国秘密支持 +0.15。
- 驻军强大 -0.20。
- 近期成功镇压 -0.10，但长期怨恨增加。

结果由双方组织力、资源、领袖能力和外援决定，而不是固定文本。

3. 意图系统
-----------

人物与势力不是等待事件落到头上，而是提出行动：

- 统治者提高税率以支付城墙建设。
- 商人联盟游说签订贸易协议。
- 继承人争取宗教组织支持。
- 受压制群体组织叛乱。
- 邻国利用动乱发起入侵。

行动选择可使用“效用分数 + 小幅随机扰动”：

utility = goal_value + personality_modifier + expected_gain - risk - cost

随机扰动不能盖过明显的状态差异。

4. 影响系统
-----------

事件影响使用结构化 Effect，示例：

- ModifyPopulation(settlement_id, group_id, -120)
- ModifyRelationship(a, b, hostility=+0.2)
- TransferControl(settlement_id, old_faction, new_faction)
- AddInstitution(settlement_id, institution_id)
- KillPerson(person_id, cause)
- CreateClaim(faction_id, target_id, claim_type)
- StartProcess(process_type, participants)

这样才能测试事件是否真正改变了世界，而不是只生成一句描述。


八、人物、家族与政治连续性
==========================

1. 人物创建策略
---------------

为控制规模，只创建三类人物：

- 制度要求的人物：统治者、继承人、主要官员。
- 事件产生的人物：叛军领袖、将军、发明者、宗教领袖。
- 潜在历史人物：高能力、高野心或重要家族成员。

普通人继续以 PopulationGroup 表示。

2. 生命周期
-----------

- 出生和亲缘关系。
- 成年后形成目标和职位候选资格。
- 婚姻改变家族义务和继承主张。
- 职位、声望和关系随事件变化。
- 年龄、疾病、战争和谋杀可能导致死亡。
- 死亡触发继承、纪念、政治真空或复仇。

3. 继承系统
-----------

继承结果应读取：

- 当前继承制度。
- 候选人的血缘或制度资格。
- 候选人的势力支持。
- 合法性和个人声望。
- 军事控制力。
- 外国支持。

结果可以是顺利继承、摄政、共同统治、政变、内战或分裂。

4. 历史人物的兑现原则
---------------------

“日后将被载入史册”之类文本只能在人物确实产生后续影响后由后世记录写出。出生时的记录不应预知未来。


九、经济、资源与地理
====================

1. 简化经济闭环
---------------

每个聚落至少模拟：

- 粮食：决定生存和人口增长。
- 木材或石材：决定建设能力。
- 金属：决定工具、贸易和军备。
- 奢侈品：影响财富、精英忠诚和贸易。
- 财政：决定政府行动能力。

年度闭环：

资源产出 -> 本地消费 -> 库存变化 -> 价格压力 -> 贸易 -> 税收 -> 公共支出

不需要模拟每笔交易，只保存总量和趋势。

2. 地理的历史作用
-----------------

- 河谷提高农业产量，但增加洪水与材料腐朽风险。
- 山口控制贸易和军事通道。
- 矿产推动财富、工匠阶层和战争竞争。
- 海岸或河流降低运输成本。
- 边远地区更难被中央控制，也更容易保存独特文化。
- 距离必须影响贸易、外交、迁徙、战争和消息传播。

3. 建设项目
-----------

建设改为持续过程，需要资源、财政和时间：

- 灌溉提高粮食产量，但维护不足会失效。
- 道路提高贸易和军队移动速度。
- 城墙提高防御，却增加税负和民怨。
- 档案馆提高记录复制率和保存率。
- 神殿提高宗教组织影响力。


十、外交、战争与领土
====================

1. 外交记忆
-----------

贸易、援助、背叛、战争、联姻和条约都应修改 Relationship。事件生成器应读取这些关系，而不是随机挑选任意两个聚落。

2. 战争作为过程
---------------

战争至少包含：

- 战争目标：领土、资源、继承、复仇、宗教或防御。
- 动员阶段。
- 若干关键行动或战役。
- 人口、财政和关系成本。
- 和平条件或政权变化。
- 战后占领、赔款、难民、复仇和记忆。

3. 战争结果
-----------

不应只有“聚落存活或毁灭”。可能结果包括：

- 边境资源点易手。
- 附庸关系。
- 赔款与债务。
- 统治者被替换。
- 人口迁移。
- 城墙、市场或档案馆损坏。
- 聚落被洗劫但继续存在。
- 聚落彻底毁灭。

彻底毁城应是低频且有充分原因的结果。


十一、文化、制度与时代
======================

1. 文化特征
-----------

文化以少量可组合标签表示，例如尚武、重商、祖先崇拜、海洋传统、书写传统。标签会影响行动偏好和记录方式，但不直接决定善恶。

2. 技术传播
-----------

技术不只产生一次发现事件，还要有：

- 发明地点和人物。
- 采用成本。
- 通过贸易、迁徙、征服或学者传播。
- 对生产、战争、记录保存和建设的持续影响。

3. 时代识别
-----------

时代不是随机命名，而是模拟结束后根据结构变化识别：

- 建城时代。
- 商路扩张期。
- 王朝统一期。
- 连年灾荒期。
- 战国期。
- 重建与文化复兴期。

时代标签用于组织时间线和叙事，不反向强制事件发生。


十二、真实历史、记录与证据
==========================

1. 记录生成
-----------

事件发生后，不是直接生成固定物证清单，而是先决定谁会记录：

- 政府记录有利于统治合法性的版本。
- 失败方可能保存流亡叙事。
- 商人关注价格、路线和损失。
- 宗教组织把事件解释为神意。
- 目击者只知道局部情况。
- 后世史家会引用旧记录并引入新的错误。

记录内容由“作者知道什么、作者想让读者相信什么、载体能容纳什么”共同决定。

2. 证据形成
-----------

证据来源分为：

- 有意制作：碑文、法令、账簿、墓葬、纪念物。
- 行动遗留：兵器、烧毁层、建筑改造、乱葬坑。
- 环境痕迹：沉积层、花粉变化、水渠废弃。
- 传播副本：抄本、译本、歌谣、转述。

同一事件可以没有任何直接记录，也可以留下彼此冲突的多份记录。

3. 信息损失
-----------

衰变不仅降低 durability，还应损害内容：

- 日期数字缺失。
- 人名只剩一部分。
- 地名被后世误认。
- 文本段落不可读。
- 口述传统合并了两个人物。
- 抄写者把胜负方写反。

物理损坏和语义损坏应分开保存。

4. 伪造与篡改
-------------

只在有明确动机时生成：

- 新王朝伪造古老血统。
- 神殿重刻碑文以证明土地所有权。
- 叛乱者散布夸大战果的歌谣。

伪造不是随机噱头，它必须服务于某个行动者目标，并留下可调查的不一致之处。


十三、玩家调查与知识系统
========================

1. 信息公开规则
---------------

- `events/history` 不再展示真实完整年表。
- 默认只展示玩家已经推断出的事件。
- 调试模式可用单独参数查看真实历史，例如 `--debug-truth`。
- `search` 只搜索玩家知识库和已访问档案，不搜索世界真相。

2. 调查动作
-----------

建议逐步加入：

- examine：观察物理特征并提取基础线索。
- date：使用地层、材料或文字风格估算年代范围。
- translate：解读文字，受语言知识和损坏程度影响。
- compare：比较两件证据中的共同与冲突主张。
- ask：向人物询问其知道或愿意透露的内容。
- research：在档案馆、神殿或私人收藏中查找记录。
- infer：由玩家提交两个实体或事实之间的假说。
- timeline：查看玩家当前重建的时间线。

3. 事实与置信度
---------------

知识库中的事实采用结构化 Claim：

- subject、predicate、object。
- time_range。
- supporting_evidence_ids。
- contradicting_evidence_ids。
- confidence。
- status：传闻、可能、可信、高度可信、已证实。

置信度由来源独立性、证据类型、保存质量、作者动机和相互印证计算。不同抄本若来自同一原本，不能被当作完全独立的三份证据。

4. 调查反馈
-----------

系统不应立即提示“正确答案”，而应告诉玩家：

- 新发现了哪些可观察事实。
- 哪条已有假说得到支持或遭到质疑。
- 哪些矛盾仍未解决。
- 下一步可能去哪里寻找信息。

5. 胜利与阶段目标
-----------------

游戏不必只有唯一终局，可设置调查委托：

- 确认某座城市毁灭的原因。
- 判断某位君主是否合法继位。
- 找出战争真正的发起方。
- 重建失落技术的传播路线。
- 识别一份关键文献是否为伪造。

评价依据是证据覆盖率、解释一致性和置信度校准，而不是是否收集全部物品。


十四、叙事生成设计
==================

1. LLM 的职责
-------------

LLM 可以：

- 把结构化观察转成自然语言。
- 根据作者身份生成不同风格的历史记录。
- 在严格事实约束下描述场景。
- 对残缺内容使用明确的不确定措辞。

LLM 不可以：

- 决定事件是否发生。
- 修改状态。
- 补充上下文中不存在的人物、日期或因果关系。
- 向玩家泄露证据尚未支持的真实历史。

2. Prompt 输入分区
-----------------

每次生成应明确分为：

- KNOWN_FACTS：允许确定陈述的事实。
- OBSERVATIONS：玩家当前可见的物理特征。
- CLAIMS：来源声称但未必真实的内容。
- UNCERTAINTIES：必须保留的不确定点。
- FORBIDDEN_FACTS：模拟器知道但玩家不得获知的内容，不应发送给模型更稳妥。

3. 输出校验
-----------

- 模型输出后检查专名、年份和数字是否来自允许集合。
- 关键事实使用模板渲染，LLM 只补充感官和语言风格。
- 缓存键必须包含证据状态、玩家知识版本和叙事视角。
- 模型失败时，模板模式必须表达相同的信息边界。

十六、模拟算法建议
==================

年度主循环伪代码：

for year in years:
    environment.update(world, year)
    economy.produce_and_consume(world, year)
    population.update(world, year)
    persons.update_lifecycle(world, year)

    pressures = pressure_engine.calculate(world, year)
    intents = intent_engine.propose(world, pressures, year)
    selected = scheduler.select_compatible(intents)
    resolutions = resolver.resolve(world, selected, year)

    for resolution in resolutions:
        validate_effects(resolution.effects)
        apply_effects(world, resolution.effects)
        event = event_factory.from_resolution(resolution)
        world.add_event(event)
        records = record_factory.create(world, event)
        evidence_factory.materialize(world, event, records)

    processes.advance(world, year)
    evidence.decay_and_propagate(world, year)
    invariants.validate(world)

事件调度器需要处理互斥，例如同一个人在同一年不能同时成为两场相距很远战争的指挥官，也不能在死亡后继续提出行动。


十七、配置与平衡
================

1. 配置外置
-----------

将以下内容从代码概率拆到版本化配置文件：

- 压力公式权重。
- 事件规则阈值。
- 人物特征影响。
- 资源产出与消费。
- 战争成本。
- 记录生成概率。
- 材料衰变和语义损失。

2. 事件预算
-----------

为控制噪声，每个聚落每年设置重要度预算：

- 重大事件不设硬上限，但必须满足严格条件。
- 中等事件按压力得分选择少量最有意义的候选。
- 日常纹理事件按年份汇总。
- 同类型事件设置冷却或升级机制。

3. 调试解释
-----------

调试输出应能显示：

- 候选事件得分。
- 触发和未触发原因。
- 随机数来源。
- 状态影响前后值。
- 事件因果父节点。

这对平衡历史合理性至关重要。


十八、存档与可复现性
====================

- 所有随机模块使用由 world seed 和稳定命名空间派生的独立 RNG。
- 禁止依赖字典迭代顺序决定随机调用次序。
- 世界存档包含 schema_version、seed、配置版本和当前年份。
- 玩家知识和真实世界分开保存，避免调试信息意外泄露。
- 每个事件保留 trigger_factors 和 effects，便于重放和定位问题。
- 允许导出仅含真实历史的开发者报告，用于测试，不作为普通游戏功能。


十九、测试方案
==============

1. 单元测试
-----------

- 压力公式边界。
- 人物年龄、死亡和继承资格。
- 关系增减和自然衰减。
- Effect 应用与回滚前验证。
- 材料衰变和内容损失。
- 证据来源依赖判定。
- 玩家置信度计算。

2. 不变量测试
-------------

- 死亡人物不能发起新行动。
- 聚落人口和资源不能为负数。
- 每位人物引用的父母、配偶和势力必须存在。
- 已解散势力不能继续控制聚落。
- 事件 effects 应与事件后状态一致。
- 证据创建年份不能早于来源事件。
- 复制品必须引用有效原本或明确标记原本已失传。
- 玩家知识不能包含未通过发现流程获得的真相字段。

3. 确定性测试
-------------

同一 seed、年份和配置应生成完全相同的：

- 实体 ID。
- 年度状态摘要。
- 事件因果图。
- 记录和证据状态。

4. 长期模拟测试
---------------

批量运行至少 100 个 seed，每个 300 至 500 年，统计：

- 聚落存活率和毁灭原因。
- 事件类型分布。
- 因果链平均长度。
- 孤立重大事件比例。
- 王朝平均寿命。
- 战争持续时间和毁城率。
- 人物参与多个事件的比例。
- 证据保存率与材质差异。
- 可由现存证据支持的真实事实比例。

5. 历史深度指标
---------------

建议建立可自动比较的指标：

- Causal Coverage：有明确 cause_event_ids 的重要事件比例。
- Consequence Coverage：产生至少一个持续状态影响的重要事件比例。
- Recurring Actor Ratio：重要人物参与两个以上事件的比例。
- Chain Depth：重要事件因果图的平均和最大深度。
- Evidence Ambiguity：存在多种合理解释的调查主题比例。
- Independent Corroboration：可由独立来源互证的事实比例。
- Event Noise Ratio：没有状态影响、没有后续引用的事件比例。

目标不是让数值越高越好，而是防止系统退回大量孤立随机事件。


二十、分阶段实施计划
====================

阶段 0：建立安全网
-----------------

目标：在重构前锁定当前确定性和基本行为。

- 增加 seed 确定性测试。
- 增加 World、Settlement、Event、Evidence 的序列化快照。
- 统计现有事件分布和证据状态作为基线。
- 将 GameREPL 从 main.py 拆出，但不改变行为。

完成标准：相同 seed 的原有模拟结果稳定，基础查询接口有测试。

阶段 1：结构化影响与因果事件
---------------------------

目标：让事件真正成为状态变化记录。

- 新增 Effect、EventRule、PressureSnapshot。
- 为现有经济、灾害、建设、战争和叛乱事件定义前置条件与影响。
- 增加 cause_event_ids、trigger_factors 和 process_id。
- 降低独立随机 pulse 权重。
- 建立事件因果图和调试报告。

完成标准：80% 以上重要事件有结构化影响，孤立重大事件明显下降。

阶段 2：人物、家族、势力与继承
-----------------------------

目标：建立政治连续性。

- 引入 Person、Family、Faction。
- 将统治者名字替换为 person_id。
- 实现生命周期、职位、婚姻、死亡和继承。
- 让战争、发现、叛乱和条约引用真实人物。
- 删除出生时预知未来的叙述。

完成标准：主要统治者和历史人物能跨多个事件持续活动，死亡后不会再出现。

阶段 3：经济、资源、外交和历史过程
-----------------------------------

目标：让地理和长期压力成为历史动力。

- 引入粮食、建设材料、金属、财政和简化贸易。
- 生成资源点和贸易路线。
- 实现 Relationship 和长期外交记忆。
- 把战争、叛乱、建设和瘟疫改为 HistoricalProcess。
- 丰富战争结果，降低无条件毁城概率。

完成标准：多数战争、贸易和叛乱都能从资源、关系或政治压力中解释。

阶段 4：记录、证据与信息损失
-----------------------------

目标：把历史真相与玩家可见内容分开。

- 引入 HistoricalRecord。
- 将证据配方改为“主体生成记录 + 行为遗留痕迹”。
- 实现语义损坏、抄本依赖、传播、伪造和篡改。
- 保留现有材质耐久系统并扩展它。
- 上下文构建器禁止直接传入完整真实事件。

完成标准：同一事件可以留下冲突版本，单件证据通常不能直接还原全部事实。

阶段 5：玩家知识图谱与调查玩法
--------------------------------

目标：让发现历史成为真正的游戏循环。

- 用 PlayerKnowledge 替换简单 known_events。
- 实现 Claim、支持、冲突和置信度。
- 修改 journal、history 和 search 的信息边界。
- 添加 compare、date、translate、research、infer 和 timeline。
- 加入第一批调查委托。

完成标准：玩家必须组合多份证据才能稳定完成调查目标，真实年表默认不可见。

阶段 6：叙事约束、平衡与内容扩展
---------------------------------

目标：提高可读性和长期多样性。

- 重构 prompt 上下文分区。
- 增加输出事实校验。
- 识别时代并生成编年摘要。
- 批量运行 seed 做平衡。
- 在系统稳定后再增加宗教传播、迁徙、法律改革等内容。


二十一、第一轮最小可行改造
==========================

不建议立即实现整套文明模拟。第一轮可限定为以下内容：

1. 新增五个持续状态
-------------------

- food_stock
- treasury
- stability
- legitimacy
- settlement_relationships

2. 改造五类关键事件
-------------------

- economic
- construction
- disaster
- rebellion
- war

3. 建立四条可验证事件链
-----------------------

- 连续歉收 -> 粮食不足 -> 稳定下降 -> 叛乱或迁徙。
- 贸易繁荣 -> 财政增加 -> 城墙建设 -> 税负或安全变化。
- 战争失败 -> 合法性下降 -> 继承危机或叛乱。
- 灾害 -> 人口与设施损失 -> 重建、外援或长期衰落。

4. 增加最小人物系统
-------------------

只模拟统治者、继承人、叛军领袖和将军，实现年龄、死亡、职位和继承。

5. 增加最小记录分层
-------------------

每个重大事件至少生成：

- 一份参与方记录。
- 一种行动遗留物证。
- 可选的民间版本。

玩家检查证据只获得 claimed_facts，不直接获得真实 event.details。

这一轮已经能显著改善历史深度，同时控制改造范围。


二十二、完整示例
================

以下示例说明目标系统如何产生一段有因果、人物和证据冲突的历史。

第 12 年：Ironvale 附近发现铁矿
--------------------------------

原因：探矿意图由高金属需求和山地资源潜力触发。

影响：
- 新建铁矿资源点。
- 金属产量提高。
- 工匠和矿工人口增长。
- 商人势力开始关注该城。

证据：勘探笔记、早期矿坑、含铁矿渣。

第 18 年：领主提高矿税
----------------------

原因：领主准备修建城墙，财政不足。

影响：
- 财政收入增加。
- 矿工满意度下降。
- 商人联盟与领主关系恶化。
- 城墙建设过程启动。

记录：官方法令强调“防御需要”，商人账簿记录成本上升。

第 21 年：歉收导致粮价上涨
--------------------------

原因：干旱降低粮食产量，矿业人口又扩大了粮食需求。

影响：
- 粮食库存跌破安全线。
- 矿工群体不满超过阈值。
- 邻城 Goldmere 通过商路控制粮食输入。

第 22 年：矿工叛乱
------------------

原因链：铁矿发现 -> 矿业扩张 -> 加税 -> 干旱歉收 -> 粮价上涨。

人物：矿工领袖 Thalric、领主 Caedor、Goldmere 商人代表 Eriven。

结果：叛军占领矿区，但未攻下城堡。Goldmere 秘密提供粮食以换取矿权承诺。

记录：
- 官方碑文称叛军受外国煽动，省略税收问题。
- 矿工歌谣称领主故意焚烧粮仓，实际没有证据支持。
- 商人密信证明 Goldmere 提供了粮食，但没有提到武器。

第 23 至 25 年：边境战争
-------------------------

原因：领主截获部分密信，认定 Goldmere 干涉内政。

过程：动员、矿区争夺、围城和谈判。

结果：Ironvale 保住城市，但承认 Goldmere 的部分矿石贸易权；领主威望下降，城墙未能完工。

第 31 年：继承危机
------------------

原因：Caedor 在旧伤恶化后死亡，合法继承人年幼；Thalric 已成为有影响力的地方领袖。

结果：摄政委员会成立，矿工获得议席，税制改革。

后世影响：这套委员会制度持续数十年，被后来的官方历史描述为领主“主动赐予”的改革。

百年后玩家可能发现：

- 重刻过的官方碑文。
- 只剩半页的矿税法令。
- 三份源自同一原本的编年史抄本。
- 矿工歌谣的两个版本。
- Goldmere 商人的密信。
- 矿区烧毁层和未完成的城墙。

玩家必须判断：叛乱的主要原因是什么、Goldmere 介入到什么程度、委员会究竟是改革还是妥协。系统内部有真实过程，但证据只允许玩家得到具有置信度的解释。


二十三、风险与控制措施
======================

1. 系统复杂度失控
-----------------

控制方法：按阶段引入；优先模拟具有历史意义的实体；普通人口保持聚合；每个新系统必须至少连接两个现有系统。

2. 模拟停滞
-----------

过强前置条件可能导致多年无事。可使用“背景压力积累”和低重要度汇总事件维持世界变化，但不能退回无条件随机事件。

3. 正反馈导致世界快速毁灭
-------------------------

战争、饥荒和叛乱可能互相放大。需要恢复机制、援助、迁徙、投降、附庸和重建，毁城必须是少数结果。

4. 事件过多导致不可读
---------------------

使用重要度、历史过程、时代摘要和事件预算；玩家界面优先展示调查相关内容。

5. 证据过于模糊导致无法推理
---------------------------

每个调查主题在生成后运行“可解性检查”：确保至少存在一组能够支持主要结论的独立证据路径，同时允许部分次要问题永远无法确定。

6. LLM 产生事实泄漏
-------------------

只发送玩家允许知道的上下文；关键事实模板化；对输出中的专名、日期和数字做校验。


二十四、最终验收标准
====================

完成主要改造后，一个 100 年世界应满足：

- 至少存在 3 条跨越 10 年以上、包含 4 个以上关键事件的因果链。
- 多数重大事件能展示触发因素、行动者和持续影响。
- 至少一半重要人物参与两个或更多相关事件。
- 战争和叛乱能追溯到资源、关系、制度或人物目标。
- 地理至少通过资源、交通、灾害和保存条件四种方式影响历史。
- 同一重大事件通常存在两个以上来源，其中部分来源具有偏见或信息缺失。
- 玩家无法通过单件普通证据直接获得完整真相。
- 默认界面不泄露真实完整年表。
- 至少一个调查任务需要交叉验证三类证据。
- 同一 seed 和配置可完全复现。
- 无人物死后行动、负人口、悬空引用等核心不变量错误。


二十五、结论
============

HistoryFinder 下一阶段不应继续以增加随机事件模板为重点。最重要的改造顺序是：

持续世界状态 -> 压力与行动 -> 结构化影响 -> 人物和势力连续性 -> 历史过程 -> 多视角记录 -> 玩家知识与推理

现有地理、事件类型、证据材质和 LLM 叙事接口都可以继续使用，但它们需要围绕新的因果核心重新组织。只要第一轮先完成结构化影响、四条事件链、最小人物系统和真实历史/记录分层，项目的历史质感就会从“随机年表”明显转向“能够被调查和解释的过去”。
