HistoryFinder 玩家玩法与调查闭环构想
=====================================

文档状态
--------

本文记录当前玩家主要玩法，以及未来 Phase D“玩家假说系统”的设计方向。
Phase D 目前暂缓，不立即实现。本文件用于保留设计意图，避免后续开发只扩充世界生成，
却失去玩家如何接触、判断和解释历史的核心目标。


一、玩家身份
============

玩家是一名在程序生成世界中旅行的调查者，而不是能够直接查看历史真相的观察者。

玩家接触到的只有：

- 聚落、废墟和其他可到达地点。
- 保存在具体地点、建筑、容器或人物手中的物理证物。
- 证物表面可以直接观察到的材质、颜色、损坏、笔迹和加工痕迹。
- 文书中仍然能够辨认的原文。
- 当地知情人真正掌握并愿意复述的说法。
- 玩家自己做过的比较、整理和假说。

玩家不能直接读取模拟器内部的 HistoricalEvent、event_id、真实参与者或真实结果。
世界模拟产生的是“过去实际发生过什么”，玩家玩法处理的是“现在还能找到什么，
这些材料声称什么，以及玩家准备相信什么”。


二、核心体验
============

游戏的核心不是收集一组自动揭晓答案的任务物品，而是在不完整、有偏见、会损毁、
会转抄和会失传的信息中建立解释。

一段历史可能同时留下：

- 一份官方记录，声称本方获得胜利。
- 一首当地歌谣，声称双方都付出了代价。
- 一件带有修补和撞击痕迹的器物。
- 一份后世抄本，其中部分文字已经发生变化。
- 一名听过旧故事的长者，但其知识经过了数代口述传承。

系统不应自动把这些内容压缩成“真实结论”。玩家需要判断哪些材料是独立来源，
哪些只是同一底稿的复制，哪些说法在时间上真正冲突，哪些差异可能来自不同年代。


三、当前主要玩法循环
====================

1. 前往地点
-----------

玩家查看已知地点并前往现存聚落或废墟。

当前调试命令：

- locations / map
- travel to <聚落名>
- look

旅行的第一层作用是改变玩家能够接触的证物和知情人。不同聚落保存着不同记录，
已经毁灭的聚落不再提供当地活跃知情人，但可能保存废墟、埋藏物和残损文书。

未来可以增加距离、路线、时间、费用和危险，但这些不是当前调查闭环的前置条件。


2. 发现并检查证物
-----------------

玩家在当前地点查看可见证物，然后选择具体对象进行检查。

当前调试命令：

- look
- examine <编号或名称>

examine 只产生客观 Observation，例如：

- “可见载体材质为羊皮纸。”
- “数行墨迹被水渍晕开。”
- “正文旁有另一种笔迹留下的短注。”
- “连接处残留铆钉。”

它不能产生以下结论：

- “这是某场战争留下的武器。”
- “这份文书证明某座城市战败。”
- “这件证物属于某位历史人物。”

检查结果会进入调查日志，并成为后续阅读、咨询和比较的输入。


3. 阅读文书
-----------

玩家只能阅读已经检查过的文书。

当前调试命令：

- read <编号或名称>

阅读结果受以下因素约束：

- 文书是否仍有书写内容。
- 载体是否已经损毁。
- 墨迹和页面的可辨识程度。
- 玩家是否理解对应语言。

调查日志保存玩家实际看见的文字片段，而不是保存一份自动恢复的完整原文。
从文字中整理出的历史内容仍然只是“这份文书声称什么”，不是事实确认。


4. 寻找并咨询知情人
-------------------

玩家可以查看当地仍然活着、仍然可接触的知情人，并向他们出示证物。

当前调试命令：

- consultants
- present <证物> to <身份或姓名>

当前知情人角色包括：

- scholar：擅长学术材料、书写传统和部分理论文献。
- scribe：擅长文字、档案和行政记录。
- elder：掌握地方口述和社区记忆。
- merchant：熟悉商路、货物、账目和交易习惯。
- artisan：熟悉材质、制作、连接、修补和磨损。

知情人只能使用其真实持有的 KnowledgeEntry 和专业能力。他们不能通过证物内部的
event_id 临时得知历史答案。

知情人会衰老和死亡。后继者只能继承前任实际掌握的部分知识；每次传承都会增加
transmission_depth，并降低 certainty。持久知情人因此是历史保存过程的一部分，
不是永远存在的答案接口。


5. 比较证物
-----------

玩家可以比较两件已经检查过的证物。

当前调试命令：

- compare <证物A> with <证物B>

比较可以指出：

- 材质是否相同。
- 保存程度是否接近。
- 表面、形制、书写和标记是否存在共同特征。
- 已知来源谱系是否相同、不同或仍然未知。

比较必须保留限制：外观相似只能提供后续核查线索，不能单独证明两件证物具有共同
历史归属。原件与抄本即使外观不同，仍可能属于同一个 source_group；相反，两件
外观相似的物品也可能没有共同来源。


6. 整理调查日志
---------------

当前调试命令：

- journal observations
- journal texts
- journal statements
- journal claims
- journal conflicts
- journal comparisons

调查日志按信息性质分层保存：

- observations：玩家亲自得到的客观观察。
- texts：玩家实际辨认出的文书原文片段。
- statements：知情人和其他来源明确说过的话。
- claims：根据有来源陈述整理出的结构化历史主张。
- conflicts：时间重叠且对象互斥的未解决冲突。
- comparisons：玩家做过的证物比较及其限制。

每条 KnownClaim 必须能够回溯到具体 SourceStatement、Evidence 和 source_group。


四、来源与置信度
================

1. 独立来源
-----------

source_group 表示一条信息谱系，而不是一件物理副本。

- 一份原件和它的所有抄本只算一个来源组。
- 同一口述传统的多名复述者只算一个来源组。
- 同一件证物交给多位专家，不会增加历史来源数。
- 不同来源组才会提高 source_independence。

副本可能提高可读性和保存机会，但不能伪装成新的独立证词。


2. 可解释置信度
---------------

主张的置信度不是“系统判断真相的概率”，而是当前调查材料对该主张的支持强度。

当前保存的组成项包括：

- carrier_quality：载体保存质量。
- directness：陈述与载体的直接程度。
- expertise_match：咨询者专业是否匹配。
- comprehension：语言与文字理解程度。
- temporal_proximity：记录年代与所述年代的接近程度；资料不足时保持为零。
- source_independence：独立来源组数量。
- corroboration：不同来源类型之间的相互印证。
- contradiction：强冲突惩罚。
- bias_penalty：已知立场与制度偏差。
- transmission_penalty：抄写或口述传承损耗。

玩家主要看到“传闻、可能、可信、高度可信”等等级，同时可以查看具体加减原因。


3. 冲突
-------

不是所有不同说法都互相冲突。

自动强冲突必须同时满足：

- subject 和 predicate 相同。
- object 互斥。
- predicate 属于明确的 exclusive 类型。
- 两条说法的 time_range 实际重叠。

例如，同一场战争在重叠年代出现“进攻方获胜”和“防守方获胜”，可以形成强冲突。
同一城市在相隔数十年的两场战争中得到不同结果，不应自动冲突。文学作品、灾害、
建筑和贸易对象通常可以同时存在，也不能只因为 object 不同就判定矛盾。


五、当前版本的游戏性质
======================

当前版本已经具备可操作的调查循环，但仍然属于系统原型和调试玩法。

已经具备：

- 世界旅行和地点查看。
- 物理证物及其保存位置。
- 无 LLM 的客观证物描述。
- 文书原文、损坏可读性和语言边界。
- 持久、会死亡并传承有限知识的知情人。
- 来源分组、置信度、冲突和证物比较。
- 可序列化的玩家调查日志。

尚未具备：

- 正式游戏 UI。
- 明确任务、委托或调查目标。
- 玩家主动建立和编辑历史假说。
- 将材料标记为支持、反对、背景或未决。
- 多个竞争解释的并列评估。
- 调查完成条件、结算和奖励。
- 旅行成本、物品携带、访问许可和社会关系等外围玩法。

因此，当前玩家可以“探索并整理材料”，但还不能正式提交自己的历史解释。


六、暂缓的 Phase D：玩家假说系统
=================================

Phase D 是未来调查闭环的关键阶段，目前仅保留设计，不开始实现。

1. 目标
-------

让玩家从系统自动整理的 KnownClaim 之外，主动提出自己的解释，并决定哪些材料与该
解释有关。系统负责检查来源、时间、支持和冲突，但不替玩家宣布历史真相。


2. 假说数据
-----------

每个 Hypothesis 建议保存：

- id
- title_cn
- subject
- predicate
- proposed_object
- proposed_time_range
- notes
- supporting_statement_ids
- contradicting_statement_ids
- context_observation_ids
- unresolved_statement_ids
- alternative_hypothesis_ids
- evaluation
- status

status 可包括：

- draft
- plausible
- supported
- disputed
- abandoned


3. 玩家操作
-----------

第一版可以使用结构化 REPL 命令验证，不依赖自然语言解析：

- hypothesis create <subject> | <predicate> | <object> | <start>..<end>
- hypothesis list
- hypothesis show <id>
- hypothesis link <id> support <statement_id>
- hypothesis link <id> contradict <statement_id>
- hypothesis link <id> context <observation_id>
- hypothesis link <id> unresolved <statement_id>
- hypothesis evaluate <id>
- hypothesis abandon <id>

未来正式 UI 应使用表单、来源列表和材料关联操作替代命令行。


4. 评估原则
-----------

HypothesisEvaluation 只能读取玩家已经获得的 Observation、SourceStatement、
KnownClaim、ComparisonResult 和 source_group。

评估应回答：

- 有多少独立来源组支持该假说。
- 支持材料是否只是同一原件的副本。
- 是否存在时间不重叠的问题。
- 是否存在强冲突。
- 是否有不同类型的材料相互印证。
- 哪些关键问题仍然没有材料回答。
- 是否存在同样合理的竞争假说。

评估不能读取 HistoricalEvent，也不能因为假说碰巧与模拟真相一致就提高分数。


5. 预期闭环
-----------

恢复 Phase D 后，完整玩法应形成以下循环：

旅行 -> 发现证物 -> 客观检查 -> 阅读或咨询 -> 比较来源 -> 提出假说 ->
关联支持与反证 -> 寻找缺失材料 -> 修订或保留竞争解释 -> 提交调查结论

一个合格结论不一定是唯一答案。游戏可以评价调查过程是否严谨，例如来源是否独立、
是否承认冲突、是否忽略明显反证，而不必告诉玩家“你与世界真相完全一致”。


七、未来任务与胜负方向
======================

Phase D 完成后，可以再选择如何把调查系统包装成正式游戏。

可能的任务来源：

- 聚落要求调查一位旧统治者的继承合法性。
- 学者要求确认一部作品的作者和传播路线。
- 商会要求调查一条失落商路曾经连接哪些城市。
- 家族要求查明墓葬、契约和口述传统之间的关系。
- 灾后聚落要求区分自然灾害、战争破坏和后期重建痕迹。

可能的评价维度：

- 是否引用了可追溯材料。
- 是否把抄本误当作独立来源。
- 是否正确处理年代范围。
- 是否说明了反证和未决问题。
- 是否区分观察、原文、他人说法和玩家解释。
- 是否保留了合理的替代假说。

这些任务与评价只应建立在调查层之上，不应破坏“玩家无法直接读取历史真相”的原则。


八、恢复开发时的建议顺序
========================

当决定恢复 Phase D 时，建议按以下顺序实施：

1. 实现 Hypothesis 和 HypothesisEvaluation DTO 及序列化。
2. 实现假说与 statement/observation 的显式关联。
3. 实现只读取玩家知识的评估服务。
4. 增加竞争假说和未决问题。
5. 用 REPL 完成固定 seed 的端到端调查案例。
6. 最后再把调查闭环接入正式 UI、任务和结算系统。

在 Phase D 暂缓期间，可以继续完善世界内容、查看器和证物生成，但新增系统必须继续
遵守 Truth、Record、Evidence、NPC Knowledge 和 Player Knowledge 相互分离的边界。
